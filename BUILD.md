# Building markdown-preview.nvim

Reference for rebuilding this plugin after source changes (e.g. the local
image/audio handling in `app/pages/image.js`). Write once, rebuild — never
hand-edit generated files.

## Architecture (what is source vs generated vs runtime)

```
markdown-preview.nvim/
├── package.json          # ROOT deps: next@7, react@16, markdown-it, pkg, tsc … (build toolchain lives HERE)
├── src/                  # TypeScript source → compiled to app/lib  (tsc / build-lib)
├── app/
│   ├── pages/            # Next.js pages + markdown-it plugins (FRONTEND SOURCE)
│   │   ├── index.jsx     #   wires up all plugins (linenumbers, image, scroll, …)
│   │   ├── image.js      #   local image/audio/video rewriting  ← e.g. edit this
│   │   ├── audio.js      #   upgrades <audio> → compact player (seek, speed, mute)
│   │   ├── linenumbers.js#   data-source-line injection
│   │   └── scroll.js     #   sync-scroll using data-source-line
│   ├── routes.js         # HTTP routes, _local_image_ file serving + MIME (SERVER SOURCE,
│   │                     #   loaded from disk at runtime — NO rebuild needed)
│   ├── server.js         # server entry, loaded at runtime via pkg --path
│   ├── lib/              # compiled TypeScript (from src/) — server runtime helpers
│   ├── .next/            # Next.js build cache (regenerated, deletable)
│   ├── out/              # static export SERVED to the browser — GENERATED by next export
│   └── bin/              # prebuilt pkg binary (embeds node); runs server.js from disk
└── autoload/mkdp/rpc.vim # starts: app/bin/markdown-preview-<platform> --path app/server.js
                          #   (falls back to: node app/index.js --path app/server.js)
```

Key facts:

- The **browser bundle** is `app/out/_next/static/<hash>/pages/index.js`.
  It is generated from `app/pages/*` — never edit it by hand.
- The **server** (`routes.js`, `server.js`, `lib/`) is read **from disk at
  runtime** by the pkg binary (via the VM loader in `lib/app/load.js`).
  Server-side edits take effect on restart — **no rebuild required**.
- `app/package.json` only lists server runtime deps (log4js, neovim, socket.io).
  The frontend toolchain (`next`, `react`, …) lives in the **root** `package.json`.

## Prerequisites

- Node.js (any modern version works, see gotcha below for Node ≥ 17)
- npm or yarn (for installing root deps)

## One-time dependency install (at repo root)

```sh
cd <repo-root>          # e.g. ~/.local/share/nvim/lazy/markdown-preview.nvim
npm install             # or: npx --yes yarn install
```

This installs `next`, `react`, `markdown-it`, `typescript`, `pkg`, etc. into
the root `node_modules/`. Do **not** run install inside `app/` for the
frontend build.

## Build commands (from repo root)

| What changed             | Command                                            | Produces                                |
|--------------------------|----------------------------------------------------|-----------------------------------------|
| Frontend (`app/pages/*`) | `npm run build-app`                                | `app/out/` (browser bundle)             |
| Server lib (`src/*.ts`)  | `npm run build-lib`                                | `app/lib/`                              |
| Everything incl. binary  | `npm run build`                                    | `app/out/` + `app/lib/` + `app/bin/…`   |
| Watch TS (dev)           | `npm run watch`                                    | `app/lib/`                              |

`build-app` expands to:

```sh
cd app && rm -rf ./.next && next build && next export
```

`next export` regenerates `app/out/` and rewrites `out/index.html` to point at
the new hashed bundle (old hash dirs are removed).

### Node ≥ 17 gotcha (webpack 4 / next 7)

Webpack 4 uses the legacy OpenSSL provider. On Node 17+ the build may fail
with `ERR_OSSL_EVP_UNSUPPORTED`. Fix:

```sh
NODE_OPTIONS=--openssl-legacy-provider npm run build-app
```

(This is required on Node 22, which is what the fix was validated with.)

## After a build / edit

| What you changed                 | To see it                                                       |
|----------------------------------|-----------------------------------------------------------------|
| Frontend (`app/pages/*`, rebuilt) | Hard-refresh the browser preview page (`Ctrl-Shift-R`)          |
| Server (`app/routes.js`, `lib/`)  | Restart the preview server: `:MarkdownPreviewStop` then `:MarkdownPreview` (or restart nvim) |

## Verify a frontend change without a browser

1. Syntax-check the bundle:

   ```sh
   node --check app/out/_next/static/<hash>/pages/index.js
   ```

2. Extract and unit-test the compiled renderer functions (they are minified;
   use brace-balanced extraction). Example for the image/audio fix:

   ```js
   // G = audio-ext regex, z = video-ext regex, j = localizeSrc
   const q = eval('(' + <extracted html-block rule> + ')')
   q([{ content: '<img src="artifact/11-13-social-justice-part1.mp3" alt="">' }], 0)
   // → '<audio controls src="/_local_image_artifact%2F11-13-social-justice-part1.mp3"></audio>'
   ```

## Worked example: change the image/audio plugin

```sh
cd <repo-root>
# 1. edit source
$EDITOR app/pages/image.js
# 2. rebuild
NODE_OPTIONS=--openssl-legacy-provider npm run build-app
# 3. verify
node --check app/out/_next/static/*/pages/index.js
# 4. hard-refresh the preview page
```

## Notes / pitfalls

- `npm run build` (full) additionally runs `yarn && pkg …` to regenerate the
  standalone binaries in `app/bin/` and then **deletes `node_modules` and
  `.next`**. Only run it when you actually want a new release binary — for
  local dev use `build-app` / `build-lib`.
- `app/routes.js` MIME types: only `.svg` got a `content-type` before the
  audio/video fix; the handler now maps common image/audio/video extensions.
  It is served from disk, so no rebuild — just restart the preview.
- The `_local_image_` path is `encodeURIComponent`-ed on the client and
  double-`decodeURIComponent`-ed server-side (`app/routes.js`). Relative
  references are resolved against the buffer dir, then walk up ancestor
  directories (so `artifact/x.mp3` in `notes/recall/` finds
  `notes/artifact/x.mp3`).
- `data-source-line` values are 0-based (`tokens[idx].map[0]`); `scroll.js`
  reconciles with 1-based cursor lines.
- The compact audio player is a **post-render DOM pass** (`app/pages/audio.js`,
  called from `index.jsx` after every content render, same as chart/diagram
  renders). The renderer still emits plain `<audio controls>`, so the player
  degrades gracefully without JS. Features: play/pause, seek with progress
  fill, time display, speed cycling 0.5×–2×, mute. Styles are injected via a
  `<style>` element once (`mkdp-audio-style`).
